## Doporučené pořadí práce

1. **Dokončit K6 bezpečně:** review/zařadit Claude registraci auth provideru, přidat HTTP integrační testy se syntetickou zákaznicí, uzavřít e-mail provider rozhodnutí. Tenant isolation tvrdit jen pro současný single-store model.
2. **P0 security gate:** omezit/autentizovat SafeOrder Worker endpoint; ověřit všechny admin/store/webhook hranice, secrets/CORS, log PII; doložit testy.
3. **K1/K2 + K4:** čistá lokální Postgres e2e Medusa cart→NEXUS price→checkout→order; test změny ceny/varianty/množství/měny a manipulace klientem.
4. **K7 payments/mail:** pouze Stripe test mode; webhook retry/fail/cancel/amount mismatch; idempotentní entitlement po potvrzené platbě; testovací e-mail provider.
5. **K3/K8 + QR C3:** soukromé média, HMAC Worker/R2 test, kupón/voucher serverový kontrakt; souběh/replay; ověřit vytištěné QR a všech 301 cílů.
6. **C7 restore drill + C8 e2e:** C7 guard skripty jsou připravené, zbývá opakovatelná obnova pouze nad potvrzenými syntetickými daty a staging DB; potom C8 kritické API scénáře.
7. **K5 aktualizace + akceptace:** sladit smlouvu vs. master brief a matice, provést nezávislé bezpečnostní review, připravit staging cutover checklist.
8. **C5 admin a storefront až poté:** role/admin procesy a finální autorský web; nejprve API kontrakt, pak UI, následně SEO/301 a testovací nákup.
9. Fáze 2/3 až po samostatném schválení rozsahu, obsahu a rozpočtu.
